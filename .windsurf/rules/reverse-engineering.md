# Reverse Engineering Rules

When analyzing, auditing, or documenting the architecture, APIs, or internal mechanics of authorized software:

- Target must be user-owned, open-source, or covered by explicit audit permission.
- Follow a 5-step methodology: Target Classification -> Passive Reconnaissance -> Deep Analysis -> Architecture Mapping -> Structured Documentation.
- Refer to the detailed guides in `references/` for web applications, Android APKs, desktop binaries, and API traffic flows.
- Never assist with license cracking, DRM bypasses, or offensive exploit generation.
